## Defining Bits, Bytes, Words, and Blocks

| Term                   | Size                                              | Definition & Architectural Role                                                                                                                                            |
| ---------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Bit**                | 1 bit                                             | The primitive state unit (0 or 1), physically represented by charge on a capacitor or latch state.                                                                         |
| **Byte**               | 8 bits                                            | The base unit of **addressing**. Hardware address buses map uniquely to individual bytes.                                                                                  |
| **Word**               | Architecture dependent (32-bit / 4B, 64-bit / 8B) | The native data unit of the CPU. Corresponds to general-purpose register width, ALU execution width, and single-instruction memory load/store capacity (`mov rax, [rbx]`). |
| **Block (Cache Line)** | Typically 64 bytes (x86/ARM)                      | The base unit of **cache coherence and memory transfer**. Contiguous bytes moved together between RAM and CPU caches (L1/L2/L3).                                           |

A **word** in logical memory (and computer architecture generally) refers to a fixed-sized group of bits or bytes that the CPU and operating system handle as a single fundamental unit of data.

Key Characteristics of a Logical Word

- **Fixed Size:** The length of a word depends on the computer architecture (commonly 16-bit, 32-bit, or 64-bit systems).
- **Addressable Unit:** Logical memory is organized into addressable locations where a single word (or a multiple/fraction of it) represents the amount of data the CPU can fetch or process in one standard operation.
- **Abstraction:** In logical (virtual) memory, this word resides within a logical address space generated by the program or CPU, which the Memory Management Unit (MMU) later translates into a physical address in RAM

A CPU works fundamentally with words.

To a CPU, a **word** is its natural unit of data. It is the size of the internal registers, the width of the data bus, and the amount of data it can process in a single clock cycle. A word is how much the CPU works on in one instruction.

- On a **32-bit CPU**, the word size is **4 bytes** (32 bits).
- On a **64-bit CPU** (like most modern computers), the word size is **8 bytes** (64 bits).

Historically, early microprocessors like the **Intel 8008** (released in 1972) were **8-bit processors**. For those CPUs, a word was exactly 8 bits, meaning **a word was exactly 1 byte long**. In that specific architecture, the CPU fetched, processed, and moved data 1 byte at a time.


Even though modern CPUs _process_ data in 32-bit or 64-bit words, most modern logical memory is still **byte-addressable**. This means:

- Every individual byte in memory gets its own unique address.
- If a 64-bit CPU wants to read just a single byte, it will still fetch the entire 64-bit (8-byte) **word** containing that byte from memory, pull it into a register, and mask out the pieces it doesn't need. This usually doesn't take 8 memory operations, as the memory unit is capable of supplying 8 bytes directly.

You should think of memory as this big array of 1 byte size, each with it's own address. Then a word becomes a group of bytes.

### But what is a block?

A block is how much the memory system moves in one trip (usually 64 bytes). Every trip to RAM has a big fixed cost. The chip has to open a row and wait, and that wait is the same whether you ask for 1 byte or 64. So fetching small pieces wastes most of each trip.

Example: your program adds up 1000 numbers stored one after another, 8 bytes each.

- **Without blocks:** the CPU asks for number 1, waits, asks for number 2, waits, and so on. That is 1000 slow trips.
- **With blocks:** the CPU asks for number 1, and memory sends the whole 64-byte block holding it. That block already contains numbers 1 to 8. The next 7 requests are answered from the copy the CPU is holding, with no trip to RAM. Total: about 125 trips instead of 1000.

**How the address splits up:** with 64-byte blocks, the memory is cut into slots 0-63, 64-127, 128-191, and so on. For any address:

- block number = address ÷ 64
- position inside the block = address mod 64 (this)

So address 1000 is in block 15 (bytes 960-1023), at position 40.

**The CPU never receives the 64 bytes. The cache does, and the CPU only takes the 8 bytes it asked for.** Two things make that work:

**1. The 64 bytes arrive in 8 small deliveries.** The wire between RAM and the CPU chip is 64 bits (8 bytes) wide. So the block comes as a burst of 8 deliveries, 8 bytes each, one right after another.

**2. A cache sits in between.** It’s a small, fast memory on the CPU chip, organized in 64-byte slots. The 8 deliveries fill one slot. The CPU’s load instruction then reads just its 8 bytes out of that slot.

**The problem:** the CPU works in 8-byte pieces, but the slow trip to RAM is worth making only for a big piece. Something has to sit in the middle that holds big pieces but hands out small ones.

Example: the CPU runs `load the 8 bytes at address 1000`.

- Address 1000 is in the block covering 960 to 1023.
- The memory controller asks RAM for that block. RAM sends 8 deliveries, and all 64 bytes land in one cache slot.
- The CPU grabs bytes 1000 to 1007 from the slot into a register. That is exactly 8 bytes, so nothing is mismatched.
- Next, the CPU asks for address 1008. That is already in the slot, so no trip to RAM is needed.


**The names change by layer, but the idea is the same:**

- CPU cache: usually called a “cache line”, 64 bytes
- Disk/SSD: “block” or “page”, often 4 KB
- OS memory: “page”, 4 KB


Example: A 64 bit CPU needs to fetch a int (4 bytes). But it will recieve 8 bytes. How does it actually get the int?

Say the int is at addresses: (1,2,3,4)

**The CPU asks for address 1, the first byte of the int, plus a size of 4 bytes.** The instruction says “load 4 bytes starting at address 1”, and the hardware works out the rest.

**What happens next:**

1. Address 1 sits in the 8-byte row covering addresses 0 to 7, at position 1 in that row. You should think that the RAM is itself divided into words. Word 0 means bytes 0-7, 1 means 8-15, etc.
2. The memory (or cache) hands over that whole 8-byte row.
3. The selector picks positions 1 to 4, which are addresses 1, 2, 3 and 4.
4. Those 4 bytes go into the register, with sign or zero extension filling the rest.


### What a 64 bit CPU supposed to be

**A 64-bit CPU is one whose basic working size, its “word”, is 64 bits (8 bytes).** That size shows up in a few places, and they usually match:

- **Registers are 64 bits wide.** A register is one of the CPU’s tiny scratch slots, and each holds 8 bytes.
- **The math unit works on 64 bits at once.** One add instruction handles two 64-bit numbers.
- **Addresses and pointers are 64 bits.** A pointer is just a number naming a byte in memory, so it has to fit in a register.

As pointers are 64 bits, it can address max 2^64 bytes. 

**1. `int + int`: a 32-bit add**

Say `x = 2,000,000,000` and `y = 2,000,000,000`.

- Both are loaded from memory (4 bytes each) into registers.
- The compiler emits a 32-bit add (`add eax, ebx` on x86). Only the low 32 bits are added, and the upper half of the register is zeroed.
- The true answer, 4,000,000,000, doesn’t fit in a signed 32-bit number (max about 2.1 billion). The result wraps to -294,967,296. Strictly, C calls signed overflow undefined behavior, but this is what typical hardware gives.

**2. `char + char`: promoted to `int` first, then a 32-bit add**

This one surprises people. C never adds two chars as chars. It first widens both to `int`, adds them as ints, and the result is an `int`.

Say `x = 100` and `y = 100` (signed chars).

- Each is loaded as 1 byte and sign-extended to fill the register.
- The add is the same 32-bit add as above, giving 200. It does not wrap, because 200 fits easily in an int.
- The result only gets chopped if you store it back into a `char`: `char z = x + y;` keeps the lowest byte, so you get -56 (200 minus 256), and only 1 byte is written to memory.

So `x + y` is 200, but `z` is -56.

**3. `long long + long long`: a 64-bit add**

Same numbers, `x = 2,000,000,000` and `y = 2,000,000,000`.

- Each is loaded as 8 bytes.
- The compiler emits a 64-bit add (`add rax, rbx`).
- The answer, 4,000,000,000, fits in 64 bits, so you get the correct result with no wrap.
