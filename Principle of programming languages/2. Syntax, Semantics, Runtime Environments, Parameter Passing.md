
**1. Lexics, Syntax, Semantics & Attributes**

**The Three Language Boundary Layers**

The structural definition of any programming language is separated into three distinct tiers:

|Layer|What it Defines|Formal Specification / Tool|
|---|---|---|
|**1. Lexics**|Structure of basic tokens (identifiers, literals, operators, keywords, whitespace).|Regular Expressions (RE) / Lexical Analyzer (Scanner).|
|**2. Syntax**|How legal tokens combine into valid phrase structures and expressions.|Context-Free Grammar (CFG / BNF) / Parser.|
|**3. Semantics**|What a syntactically legal phrase means and does during program execution.|Context-sensitive rules, symbol tables & semantic functions.|

**Names, Attributes, and the Semantic Mapping Functions**

A **name (or identifier)** denotes a program entity (variable, function, constant, type). The meaning of a name is determined by the **attributes** bound to it.

To track program semantics during compilation and execution, three fundamental mapping functions are maintained:

1. **Symbol Table (Static Mapping)**: SymbolTable : Names→Attributes. Maps names to compile-time attributes (type, scope, size, role).
2. **Environment (Dynamic Location Mapping)**: Environment : Names→Locations. Maps names to abstract memory addresses.
3. **Memory / Store (State Mapping)**: Memory : Locations→Values. Maps memory addresses to stored data values.



**2. Binding & Binding Times**

Binding is the association of an attribute with a name. The binding time is the earliest point in the language definition or translation pipeline at which an attribute is assigned to a name.

**Stages of the Binding Time Spectrum**

1. **Language Definition:** The meaning of keywords (`if`, `while`) and boolean values (`true`/`false`) is bound here.
2. **Language Implementation:** The range of primitive types (`maxint`, floating-point precision) is bound here.
3. **Translation (Compile):** The data type of a declared variable in static languages (`int x;`) is bound here.
4. **Link Time:** External library function calls are bound to their code bodies.
5. **Load Time:** Absolute memory addresses are bound to global/static variables.
6. **Execution (Runtime):** Values are bound to variables through assignment statements (`x = 2;`).

- **Static Binding**: Occurs prior to execution (Stages 1-5).
- **Dynamic Binding**: Occurs during execution (Stage 6).


**3. Runtime Environments & Memory Allocation**

The structure of a language's **runtime environment** is determined by its support for **recursion**, **nested blocks**, and **first-class functions**.

There are 3 runtime architectures:

| Architecture                        | Language Support                                                | Characteristics & Trade-offs                                                                  |
| ----------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **1. Fully Static**                 | FORTRAN 77 (No recursion, no nested procedures)                 | Memory allocated once at load time. Fast, but cannot support recursion or dynamic data sizes. |
| **2. Stack-Based** (Stack + Heap)   | C, C++, Ada, Pascal, Java (Supports recursion & dynamic blocks) | Globals static; local variables pushed/popped on LIFO stack frames (Activation Records).      |
| **3. Fully Dynamic** (Heap-centric) | Lisp, Scheme, Haskell, Python (First-class functions, closures) | First-class functions & closures prevent pure stack cleanup; requires garbage collection.     |
