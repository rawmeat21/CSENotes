
## **Lexics, Syntax, Semantics**

The structural definition of any programming language is separated into three distinct tiers:

**Lexics**
- The structure of individual tokens: identifiers, literals, operators, white-space conventions
- Recognised by the scanner, usually specified with regular expressions.

**Syntax**
- How tokens combine into legal phrases.
- Specified by a context-free grammar (BNF / EBNF / syntax diagrams) and checked by the parser.

**Semantics**
- What a legal phrase means and does.
- Context-sensitive rules like declare-before-use, no redeclaration, type correctness, runtime behaviour.


## **Ways to specify semantics**

- **Language reference manual** 

-> This is the most common way to specify semantics. 

-> The expanding use of English descriptions has resulted in clearer and more precise reference manuals, but they still suffer from the lack of precision inherent in natural language descriptions and also may have omissions and ambiguities.


- **Defining translator**:

-> The advantage of specifying semantics by defining a translator is that questions about a language can be answered by experiment (as in chemistry or physics). 

-> A drawback is that questions about program behavior cannot be answered in advance, we must execute a program to discover what it does. 

-> Another drawback is that bugs and machine dependencies in the translator become parts of the language semantics, possibly unintentionally. 

-> Also, the translator may not be portable to all machines and may not be generally available.


- **Formal definition** 

-> Formal, mathematical and exact.

-> Mathematical methods are precise, but they are also complex and abstract, and require study to understand. Different formal methods are available, with the choice of method depending on its intended use. 

-> Denotational semantics is a good formal method to use for the description of the translation and execution of programs. It describes semantics using a series of functions.


## **Names, attributes and binding**

**Names**: Names, or identifiers, denote language entities or constructs.
**Attributes**: The meaning of a name is determined by the properties, or attributes associated with the name.

Examples:

```c
const int x=5;
```
The above statement associates to the name x to the data type attribute “integer constant” and the value attribute 5.


```c
int x;
```
This associates the attribute “variable” and the data type “integer” to the name x.


```c
double f(int n){...}
```

This associates the attribute “function” and the following additional attributes to the name f:
1. The number, names, and data types of its parameters (in this case, one parameter with name n and data type “integer”)
2. The data type of its returned value (in this case, “double”)
3. The body of code to be executed when f is called.

**Binding**: The process of associating an attribute with a name is called binding.

An attribute can be classified according to the time during the translation/execution process when it is computed and bound to a name. This is called the **binding time of the attribute.** 

Binding times can be classified into two general categories: static binding and dynamic binding. 

-> Static binding occurs prior to execution. This creates a static attribute.
-> Dynamic binding occurs during execution. This creates a dynamic attribute.

![](../assets/Pasted%20image%2020261121212850.png)

A static attribute can be bound during parsing or semantic analysis (translation time), during the linking of the program with libraries (link time), or during the loading of the program for execution (load time). For example, the body of an externally defined function will not be bound until link time, and the location of a global variable is bound at load time, since its location does not change during the execution of the program.

A dynamic attribute can be bound at different times during execution, for example, on entry or exit from a procedure, or on entry or exit from the entire program.

### **How to maintain bindings**

Bindings must be maintained by a translator so that appropriate meanings are given to names during translation and execution. A translator does this by creating a data structure to maintain the information.

To track program semantics during compilation and execution, three fundamental mapping functions are maintained:

1. **Symbol Table (Static Mapping)**: SymbolTable is a function from Names→Attributes. Maps names to compile-time attributes (type, scope, size, role).

![](../assets/Pasted%20image%2020261121213154.png)

2. **Environment**: During the execution of a compiled program, attributes such as locations and values must also be maintained. A compiler generates code that maintains these attributes in data structures during execution. The memory allocation part of this process (binding of names to storage locations) is usually maintained by the environment. It maps names to locations. 

![](../assets/Pasted%20image%2020261121213429.png)


3. **Memory / Store (State Mapping)**: The bindings of storage locations to values is called the memory. Memory maps Locations→Values.

![](../assets/Pasted%20image%2020261121213439.png)



## **Runtime Environment**

Depending on the language, the environment may be constructed statically (at load time), dynamically (at execution time), or with a mixture of the two.

**Fully static**
-> A language that uses a completely static environment is FORTRAN. All locations are bound statically.

**Fully dynamic**
-> A language that uses a completely dynamic environment is LISP. All locations are bound during execution.

**Mixed**
-> C, C++, Ada, Java, and other Algol-style languages are in the middle. Some allocation is performed statically, while other allocation is performed dynamically.

### Lifetime

The lifetime or extent of an object is the duration of its allocation in the environment. The lifetimes of objects can extend beyond the region of a program where they may be accessed.

Lifetime is different from scope:

```c
A:{

	int x;
	B:{
		double x;
	}
}
```

`A::x` is not accessible in `B` but is still allocated though `B`. 

### Aliases

Two names bound to the same location. Created deliberately by pass by reference or pointer assignment, and accidentally by overlapping arguments.


```cpp
int x=5;
int& rf=x;
```


### Heap problems

**Dangling reference**: A pointer that still refers to storage that has been deallocated. Dereferencing it reads or writes memory that now belongs to something else.

```cpp

int* p;

{
	p=&x;
}
// p is dangling
```


**Garbage**: Allocated storage that is no longer reachable by any name. Also a memory leak.

```cpp
int* p=new int{};

p=nullptr;//allocated int is not reachable by any means
```


## **Data types**

A data type is a set of values.

The declaration of x as an int says that the value of x must be in the set of integers as defined by the language.

Another definiton: A data type is a set of values, together with a set of operations on those values having certain properties.

**Why have explicit type checking**

1. Static type information allows compilers to allocate memory efficiently and generate machine code that efficiently manipulates data, so execution efficiency is enhanced.

2. Static types can be used by a compiler to reduce the amount of code that needs to be compiled (particularly in a recompilation), thus improving translation efficiency.

3. Static type checking allows many standard programming errors to be caught early, improving writability, or efficiency of program coding.

4. Static type checking improves the security and reliability of a program by reducing the number of execution errors that can occur.

5. Explicit types in a programming language enhance readability by documenting data design, allowing programmers to understand the role of each data structure in a program, and what can and cannot be done with data items.

6. Explicit types can be used to remove ambiguities in programs. Type information can be used to resolve overloading.

7. Explicit types combined with static type checking can be used by programmers as a design tool, so that incorrect design decisions show up as translation-time errors.

8. Finally, static typing of interfaces in large programs enhances the development of large programs by verifying interface consistency and correctness

### Type equivalence


#### Structural equivalence

Two data types are the same if they have the same structure: They are built in exactly the same way using the same type constructors from the same simple types.

It is used in such languages as Algol60, Algol68, FORTRAN, COBOL, and a few modern languages such as Modula-3. It is also used selectively in such languages as C, Java, and ML.

To check structural equivalence, a translator may represent types as trees and check equivalence recursively on subtrees.
