## 1. How `arr=( $(cat file.txt | uniq) )` Works

When Bash sees `arr=( $(cmd) )`, it executes the pipeline in a subshell and processes the result in four distinct phases:

```
[ Subshell Output ] ──> [ Raw String ] ──> [ Word Splitting ($IFS) ] ──> [ Glob Expansion ] ──> [ Array Elements ]
```

### Step 1: Subshell & Output Capture

Bash forks a subshell to run `cat file.txt | uniq`. It captures the standard output as a **single raw string** in memory (stripping any trailing newlines). No temp file is created.

### Step 2: Unquoted Expansion

Because `$(...)` is **unquoted** inside `arr=( ... )`, Bash does not treat the string as a single unit. It prepares the string for parsing.

### Step 3: Word Splitting (The `$IFS` Pass)

Bash inspects the string and splits it into tokens wherever it finds characters listed in the Internal Field Separator variable (`$IFS`). By default, `$IFS` contains `<space>`, `<tab>`, and `<newline>`.

- If `file.txt` contains:
    
    Plaintext
    
    ```
    foo bar
    baz
    ```
    
- Word splitting breaks this into 3 tokens: `"foo"`, `"bar"`, and `"baz"`.
    

### Step 4: Pathname Expansion (Globbing)

Bash takes every token generated by Step 3 and checks if it contains wildcards (`*`, `?`, `[...]`). If it does, Bash attempts to expand that token into matching filenames in the current directory.

## 2. Why `arr=( * )` Works Differently (and Safely)

You noted that `arr=( * )` works cleanly. The reason `arr=( * )` is safe—while `arr=( $(...) )` is not—comes down to **where the tokens come from**:

|Operation|Does Word Splitting Occur?|Handles Spaces in Items Safely?|
|---|---|---|
|`arr=( * )`|**No.** The shell globber evaluates paths directly.|**Yes.** A file named `my file.txt` becomes 1 element.|
|`arr=( $(...) )`|**Yes.** The text output is split on space, tab, and newline.|**No.** A line named `my file.txt` becomes 2 elements (`my` and `file.txt`).|

In `arr=( * )`, the shell executes Pathname Expansion directly. It scans the filesystem, finds matches, and assigns each matching file directly to an array index. No string splitting step takes place.

## 3. Failure Modes of `arr=( $(cat file.txt | uniq) )`

Because `$(...)` undergoes both Word Splitting and Globbing, it fails in two common scenarios:

### Case A: Lines with spaces split into separate array elements

Suppose `file.txt` contains unique lines of text:

Plaintext

```
Hello World
Bash Scripting
```

- **Expected Array:** 2 elements (`"Hello World"`, `"Bash Scripting"`)
    
- **Actual Array:** 4 elements (`"Hello"`, `"World"`, `"Bash"`, `"Scripting"`)
    

### Case B: Glob characters trigger unintended directory expansions

Suppose `file.txt` contains standard mathematical or formatting operators:

Plaintext

```
select * from users
```

- **Expected Array:** Words from the query.
    
- **Actual Array:** `"select"`, followed by **every single file in your current working directory** (replacing `*`), followed by `"from"`, `"users"`.
    

## Summary Syntax Matrix

Bash

```
# 1. Unsafe: Splits on spaces/newlines AND expands wildcards like *
arr=( $(uniq file.txt) )

# 2. Safe for lines: Preserves spaces within lines, no wildcard expansion
readarray -t arr < <(uniq file.txt)

# 3. Direct Globbing: Native shell array generation from paths
arr=( *.txt )
```
